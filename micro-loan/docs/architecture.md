# 小贷公司借款申请与资料收集系统 - 技术架构文档

## 项目概述

本系统是专为小贷公司设计的后端API服务，采用Go语言和Go Fiber框架开发，按照一线同事的实际处理顺序组织业务流程，实现借款申请、资料收集、风控审核、贷后管理等核心功能。

## 技术栈

- **语言**: Go 1.21+
- **Web框架**: Go Fiber v2
- **ORM**: GORM
- **数据库**: MySQL 5.7+
- **工具库**:
  - UUID生成: github.com/google/uuid

## 核心功能模块

### 1. 借款申请模块 (Loan)

**职责**: 管理借款申请的创建、查询、状态流转

**核心功能**:
- 创建借款申请
- 查询借款申请（支持详情查询）
- 分页查询借款申请列表
- 更新借款申请状态

**API前缀**: `/api/v1/customer-manager`, `/api/v1/risk-auditor`, `/api/v1/post-loan-officer`

### 2. 资料收集模块 (Document)

**职责**: 管理客户资料的收集、审核

**核心功能**:
- 上传客户资料
- 审核资料（通过/拒绝/造假）
- 幂等提交资料（防止重复提交）
- 资料造假自动预警

**API前缀**: `/api/v1/customer-manager`, `/api/v1/risk-auditor`

### 3. 风控审核模块 (RiskAudit)

**职责**: 进行风控评分和审核

**核心功能**:
- 创建风控审核记录
- 查询风控审核历史
- 获取最新风控审核结果

**API前缀**: `/api/v1/risk-auditor`

### 4. 贷后管理模块 (PostLoan)

**职责**: 管理放款后的催收、展期等业务

**核心功能**:
- 创建催收记录
- 申请展期
- 审批展期
- 逾期提醒失效检测

**API前缀**: `/api/v1/post-loan-officer`

### 5. 预警系统 (Warning)

**职责**: 自动识别和跟踪业务风险

**核心功能**:
- 资料造假预警
- 逾期提醒失效预警
- 展期口径不统一预警
- 预警处理流程

**API前缀**: `/api/v1/post-loan-officer`

### 6. 审计日志模块 (AuditLog)

**职责**: 记录所有业务操作，支持追溯和审计

**核心功能**:
- 记录操作日志
- 查询审计日志
- 按条件过滤日志

**API前缀**: `/api/v1/audit-logs`

## 角色权限设计

### 1. 客户经理 (customer_manager)
- **职责**: 发起借款申请、收集客户资料
- **入口**: `/api/v1/customer-manager`
- **权限**:
  - 创建借款申请
  - 上传客户资料
  - 幂等提交资料
  - 查询借款申请

### 2. 风控审核 (risk_auditor)
- **职责**: 审核借款申请、评估风险
- **入口**: `/api/v1/risk-auditor`
- **权限**:
  - 查询借款申请
  - 审核资料
  - 创建风控审核
  - 更新借款状态

### 3. 贷后专员 (post_loan_officer)
- **职责**: 管理放款后业务、催收、展期
- **入口**: `/api/v1/post-loan-officer`
- **权限**:
  - 查询借款申请
  - 创建催收记录
  - 申请/审批展期
  - 处理预警
  - 更新借款状态

## 预警机制

### 1. 资料造假预警 (forgery)
- **触发条件**: 风控审核标记资料造假
- **自动触发**: 是
- **处理建议**: 
  1. 核实资料真实性
  2. 与客户沟通
  3. 决定是否拒绝申请

### 2. 逾期提醒失效预警 (overdue_remind)
- **触发条件**: 逾期超过24小时且48小时未催收
- **自动触发**: 贷后专员主动检查时触发
- **处理建议**:
  1. 立即进行催收
  2. 记录催收结果
  3. 跟踪还款情况

### 3. 展期口径不统一预警 (extension)
- **触发条件**: 新展期申请与历史展期到期日不一致
- **自动触发**: 是
- **处理建议**:
  1. 核实历史展期记录
  2. 统一口径
  3. 审批展期

## 数据追溯设计

### 状态变化记录
- **表**: `status_histories`
- **记录内容**:
  - 原状态
  - 新状态
  - 变更人
  - 变更时间
  - 变更原因

### 审计日志
- **表**: `audit_logs`
- **记录内容**:
  - 操作类型
  - 操作人
  - 操作时间
  - 操作前后数据
  - IP地址
  - 用户代理

### 字段设计原则
1. **所有关键字段都存储在数据库中**
2. **状态变化记录完整历史**
3. **责任人明确记录**
4. **时间点精确到秒**
5. **备注字段支持自由说明**

## 安全考虑

### 1. 角色权限隔离
- 不同角色使用不同的API前缀
- 权限验证在应用层实现

### 2. 审计追踪
- 所有操作都记录审计日志
- 记录操作人和操作时间
- 保存操作前后数据

### 3. 数据完整性
- 使用事务确保数据一致性
- 幂等性设计防止重复提交

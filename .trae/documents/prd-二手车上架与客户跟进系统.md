# 二手车商-上架定价与客户跟进系统 PRD

## 1. 产品概述

**项目定位**：专注二手车商内部交接流程与责任追溯的管理系统

**核心价值**：通过明确的状态流转和交接留痕，解决二手车商"旧台账、现场记录、沟通截图"三者脱节导致的上架定价和客户跟进责任不清问题。

**目标用户**：二手车商收车经理、评估师、金融专员

---

## 2. 核心业务流程

### 2.1 车辆生命周期状态机

```
[车辆入库] → [等待评估] → [评估中] → [等待定价] → [等待上架确认] → [已上架] → [客户跟进中] → [成交/下架]
```

**关键原则**：
- 每个状态流转必须记录：操作人、操作时间、备注
- 状态变更不可逆，除非有特殊操作权限
- 所有状态变化实时可见，支持历史回放

### 2.2 交接链路（核心）

```
收车经理 → 评估师 → 金融专员 → 销售顾问
    ↓
  提交入库
    ↓
  发起评估请求
    ↓
  完成车辆评估 + 填写评估报告
    ↓
  提交定价建议（收车经理）
    ↓
  审核定价（评估师/金融专员）
    ↓
  确认上架（金融专员）
    ↓
  发起客户跟进（销售顾问）
    ↓
  持续跟进记录 → 成交/失败归档
```

**留痕要求**：
- 每次交接必须包含：交接人、接收人、交接时间、车辆状态、备注说明
- 交接记录不可删除，只能追加说明
- 附件支持：现场照片、检测报告、沟通截图等（占位符形式）

---

## 3. 核心功能模块

### 3.1 车辆台账管理

**列表页**：
- 支持按状态、收车经理、评估师、金融专员筛选
- 支持按入库时间、车辆品牌、车型、报价排序
- 每辆车显示：车牌号、车型、上架状态、最近跟进状态、责任人

**详情页**：
- 基础信息：车牌号、车型、上牌时间、行驶里程、收车价
- 状态时间轴：展示所有状态变更历史
- 交接记录：展示所有交接节点及详情
- 附件区域：车辆照片、检测报告、金融方案等（支持上传占位）
- 跟进记录：客户跟进的完整历史

**重点功能**：
- 状态变更操作：必须选择下一个状态、填写变更原因
- 交接操作：必须指定接收人、填写交接备注
- 历史回看：可查看任意时间点的车辆状态快照

### 3.2 上架定价处理

**定价提交流程**：
1. 收车经理提交定价建议（原价、预期售价、金融方案备注）
2. 评估师审核（可修改价格区间、添加评估说明）
3. 金融专员确认（确定最终售价、金融方案）
4. 确认上架（状态变为"已上架"）

**定价记录**：
- 每次定价修改都记录：修改人、修改时间、修改前后价格、修改原因
- 支持附件：评估报告、金融计算表等

### 3.3 客户跟进管理

**跟进记录**：
- 时间、跟进人、跟进方式（电话/微信/面谈）、客户信息、跟进内容、下次跟进时间
- 支持附件：沟通截图、客户资料等（占位）

**跟进状态**：
- 待联系 → 联系中 → 有意向 → 谈判中 → 成交/失败
- 每个状态变更必须填写备注

**重点功能**：
- 跟进回看：完整展示车辆的所有跟进历史
- 跟进提醒：显示下次跟进时间，过期高亮
- 跟进统计：按跟进人统计跟进数量和成交率

### 3.4 交接与权限

**交接类型**：
- 评估交接：收车经理 → 评估师
- 定价交接：评估师 → 金融专员
- 上架交接：金融专员 → 销售顾问
- 跟进交接：同一角色的内部转移

**交接记录字段**：
- 交接时间（自动）
- 交接人（自动）
- 接收人（必选）
- 车辆状态（自动）
- 交接备注（必填）
- 附件支持（选填）

## 4. 初始化数据要求

**必须包含历史数据**：
- 至少 3 辆车的完整生命周期记录
- 每辆车至少包含：入库记录、评估记录、一次定价记录、3-5 条跟进记录
- 每条记录必须包含：操作人、操作时间、历史备注

**示例数据结构**：
```json
{
  "id": "VEH-2024-001",
  "plate": "京A12345",
  "model": "宝马5系 2022款",
  "status": "客户跟进中",
  "timeline": [
    {
      "status": "车辆入库",
      "operator": "张伟（收车经理）",
      "time": "2024-06-01 10:30",

      "time": "2024-06-01 14:20",
```

## 5. UI 设计方向

**设计风格**：
- 专业商务风，强调效率和清晰度
- 卡片式布局，每个模块职责分明
- 状态用颜色区分：待处理（橙）、进行中（蓝）、已完成（绿）、异常（红）

**页面结构**：
- 左侧导航：台账列表、筛选、搜索
- 主内容区：车辆卡片/列表
- 详情页：左侧基础信息 + 右侧状态时间轴和跟进记录

**交互重点**：
- 状态变更和交接操作要有明显的表单和确认流程
- 历史记录支持折叠展开，避免信息过载
- 筛选和搜索要实时响应

---

## 6. 优先级排序

**第一阶段（核心链路）**：
1. 车辆列表 + 筛选
2. 车辆详情 + 状态时间轴
3. 上架定价流程
4. 客户跟进记录
5. 交接操作 + 留痕

**第二阶段（增强功能）**：
1. 跟进提醒
2. 交接统计
3. 附件上传（占位）
4. 高级筛选

**第三阶段（可选）**：
1. 数据导出
2. 批量操作
3. 移动端适配

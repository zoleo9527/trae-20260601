# 驾校运营-学时确认与费用结算系统 PRD

## 1. 产品概述

针对驾校运营中的学时确认与费用结算场景，解决练车排不上、考试名额漏抢、补考费用说不清等异常问题。通过记录完整的状态流转、责任人和时间点，实现异常情况的可追溯和可追溯。

### 核心价值
- **异常优先**：异常流程占总业务的主要部分，正常流程只是兜底
- **责任清晰**：每个状态变更都记录责任人，避免推诿
- **信息完整**：学时、费用、退款、备注在同一记录中，避免信息孤岛

## 2. 用户角色

| 角色 | 职责 | 核心待办 |
|------|------|---------|
| 招生顾问 | 学员报名、费用收取、异常协调 | 待确认学时、待结算费用、异常记录 |
| 教练 | 练车安排、学时确认、异常反馈 | 待确认练车、待审核学时、异常说明 |
| 考试专员 | 考试预约、成绩录入、补考管理 | 待预约考试、待录入成绩、待处理补考 |

## 3. 核心数据模型

### 3.1 学员档案 (Student)
- 基本信息：姓名、电话、身份证、报考类型
- 状态：报名中、学科学习中、练车中、约考中、已拿证、已毕业
- 关联：招生顾问、教练、考试记录、费用记录

### 3.2 学时记录 (TrainingHours)
- 记录类型：练车学时、考试模拟学时
- 学时状态：待教练确认、已确认、异常（排不上、时间冲突）
- 关联：学员、教练、时间段、场地

### 3.3 费用记录 (Payment)
- 费用类型：报名费、学时费、补考费、补训费、退款
- 支付状态：待支付、已支付、已结算、已退款、异常
- 关联：学员、费用项目、收款人、支付时间

### 3.4 考试预约 (ExamBooking)
- 预约状态：待预约、已预约、已参加、缺考、成绩录入中
- 关联：学员、考试类型、考试日期、考场

### 3.5 状态流转记录 (StatusLog)
- 记录每个关键业务对象的状态变更
- 必填字段：状态、责任人、时间点、备注
- 支持：学时确认、费用结算、退回原因、补充说明

## 4. 核心功能模块

### 4.1 多角色待办中心
**招生顾问待办**
- 待确认学员练车安排
- 待结算费用清单
- 异常情况协调（排不上、漏抢）

**教练待办**
- 待确认练车计划
- 待审核学员学时
- 待说明异常原因

**考试专员待办**
- 待预约考试
- 待录入考试成绩
- 待处理补考费用

### 4.2 学时确认流程
**流程状态**
1. 学员预约练车 → 待教练确认
2. 教练确认 → 待学时录入
3. 学时录入 → 待学员确认
4. 学员确认 → 已完成

**异常处理**
- 练车排不上：状态标记为"排不上"，记录原因和时间
- 教练临时有事：状态标记为"取消"，记录备选方案
- 学员迟到早退：记录实际学时，标记差异原因

### 4.3 费用结算流程
**结算状态**
1. 费用产生 → 待确认
2. 招生顾问确认 → 待支付
3. 支付完成 → 已结算
4. 需要退款 → 待退款审核

**费用类型**
- 报名费：一次性
- 学时费：按实际学时计算
- 补考费：按考试类型
- 补训费：按补训学时
- 退款：按退费政策计算

**退回原因**
- 学员退学
- 报名失败
- 费用错误
- 其他说明

### 4.4 筛选与查询
**列表筛选**
- 按状态筛选（进行中、已完成、异常）
- 按时间范围筛选
- 按责任人筛选
- 按学员姓名/电话搜索

**费用结算回看**
- 按学员查看所有费用明细
- 按时间段查看结算汇总
- 按费用类型统计

### 4.5 状态流转追踪
**记录内容**
- 状态变更时间（精确到分钟）
- 变更责任人（角色+姓名）
- 变更原因（必填）
- 备注说明（可选）

**展示方式**
- 时间轴形式展示状态历史
- 当前状态高亮
- 支持导出流转记录

## 6. 状态流转设计

### 6.1 学时状态流转
```
预约练车 → 教练确认 → 学时录入 → 学员确认 → 已完成
    ↓           ↓          ↓          ↓
   异常       拒绝      异常       异常
```

### 6.2 费用状态流转
```
费用产生 → 顾问确认 → 学员支付 → 已结算
    ↓          ↓          ↓
   退回      退回待审   退款中
```

### 6.3 考试状态流转
```
约考中 → 已预约 → 考试完成 → 成绩录入 → 已归档
    ↓                        ↓
   取消                   补考中
```

## 7. 核心场景处理

### 7.1 练车排不上
**触发条件**
- 学员预约练车但场地/教练不可用

**处理流程**
1. 系统标记"排不上"状态
2. 记录原因（场地满/教练请假/学员时间冲突）
3. 招生顾问收到待办
4. 协调后重新预约

**记录要求**
- 必须记录：原因、时间、责任人、协调方案

### 7.2 考试名额漏抢
**触发条件**
- 预约失败或取消

**处理流程**
1. 系统标记"漏抢"状态
2. 考试专员收到待办
3. 尝试捡漏或预约下一场
4. 记录处理结果

**记录要求**
- 必须记录：漏抢原因、尝试次数、最终结果

### 7.3 补考费用说不清
**触发条件**
- 学员对补考费用有异议

**处理流程**
1. 学员提出疑问
2. 招生顾问查询费用明细
3. 系统展示完整费用链
4. 如有错误，走退款流程

**记录要求**
- 必须记录：疑问内容、解答说明、确认结果

## 8. 数据审计要求

### 8.1 必记字段
- `created_at`：创建时间
- `updated_at`：更新时间
- `status`：当前状态
- `status_history`：状态变更历史（JSON 数组）
- `handler_id`：当前处理人
- `handler_name`：处理人姓名
- `handler_role`：处理人角色
- `remark`：备注说明
- `reason`：变更原因

### 8.2 状态历史格式
```json
{
  "status": "confirmed",
  "timestamp": "2026-06-14 10:30:00",
  "handler_id": "coach_001",
  "handler_name": "张教练",
  "handler_role": "coach",
  "reason": "学时确认完成",
  "remark": "实际练车2小时，无异常"
}
```

## 9. 非功能性要求

### 9.1 性能要求
- 列表查询响应时间 < 2秒
- 支持1000+学员同时在线
- 异常状态高亮显示

### 9.2 可用性要求
- 操作需二次确认
- 状态变更需填写原因
- 支持批量操作

### 9.3 安全要求
- 角色权限隔离
- 操作日志完整记录
- 敏感操作需上级审批

## 1. 产品概述

写字楼租赁-租赁报价与合同流转系统，解决房源台账、看房记录、物业交接单之间缺少交接导致房源状态更新慢、看房反馈散、押金结算争议被拖成后续问题的核心痛点。通过角色分工明确（租赁顾问→运营经理→财务）、全流程操作留痕、状态流转自动驱动，让每个环节都有判断依据和可追溯记录。

- 目标用户：写字楼租赁公司的租赁顾问、运营经理、财务人员
- 核心价值：消除信息断层，让报价审批、合同流转、押金结算每个节点"谁做了什么、为什么做"都有据可查

## 2. 核心功能

### 2.1 用户角色

| 角色 | 登录方式 | 核心权限 |
|------|----------|----------|
| 租赁顾问 | 演示账号 consultant / 123456 | 预约看房、记录反馈、创建和提交报价、起草和提交合同、发起交接、创建押金记录 |
| 运营经理 | 演示账号 manager / 123456 | 确认/拒绝报价、审核/签署合同、完成交接确认、发起押金扣除/退款 |
| 财务 | 演示账号 finance / 123456 | 确认押金到账、执行押金退款、参与扣除操作 |

### 2.2 功能模块

1. **工作台**：角色定向待办、关键数据统计、最近操作日志
2. **房源台账**：房源卡片列表、状态筛选、详情页含全关联数据（看房/报价/合同/交接/押金）及状态流转时间线
3. **看房记录**：列表与详情，支持预约、完成（记录反馈与兴趣度）、取消操作，反馈关联到房源状态
4. **租赁报价**：列表与详情，支持创建草稿、提交审批、经理确认/拒绝，报价关联看房记录和房源
5. **合同管理**：列表与详情，支持起草、提交审核、经理审核/拒绝/签署，合同关联报价单，含条款编辑
6. **物业交接**：列表与详情，支持入住/退租交接创建、接收方签字、经理完成确认，争议标记
7. **押金结算**：列表与详情，支持创建、财务确认到账、经理发起退款/扣除、财务确认退款、争议标记
8. **操作日志**：全量操作日志，支持按实体类型/操作人/动作筛选，分页浏览

## 3. 核心流程

### 3.1 租赁报价处理流程

租赁顾问在看房完成后，根据客户需求和反馈创建报价单。报价单提交后流转至运营经理审批。经理可确认（报价通过，房源进入合同起草阶段）或拒绝（报价退回修改，房源回到待报价状态）。每次操作均记录操作人和审批意见。

```mermaid
flowchart TD
    "A[看房完成]" --> "B[租赁顾问创建报价草稿]"
    "B" --> "C[租赁顾问提交报价]"
    "C" --> "D[运营经理审批]"
    "D" -->|"确认"| "E[报价通过\n房源→报价已确认]"
    "D" -->|"拒绝"| "F[报价退回\n房源→待报价\n含拒绝原因]"
    "F" --> "B"
    "E" --> "G[进入合同起草阶段]"
```

任何实体（房源、报价、合同、交接单、押金记录）的操作均有时间线记录，包含操作人、操作时间、旧状态→新状态、操作描述。支持从房源详情页查看完整生命周期，也可从具体业务页面查看该实体的操作历史。

## 5. 系统边界说明

### 5.1 未接入真实外部系统

- **支付系统**：押金到账、退款均为状态标记，未接入真实支付通道
- **电子签章**：合同签署、交接签字为文本记录，未接入CA认证或电子签章平台
- **短信/邮件通知**：状态变更不发送真实通知
- **文件存储**：合同附件为占位字段，未接入OSS/文件服务器
- **身份认证**：使用JWT + 内存数据库，未接入企业SSO/LDAP
- **数据持久化**：使用内存Map存储，服务重启数据重置（每次启动重新seed）

### 5.2 演示约束

- 所有数据为演示数据，服务重启后恢复初始状态
- 密码统一为 123456，仅供演示
- JWT密钥为硬编码值，生产环境需替换

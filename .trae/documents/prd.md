## 1. 产品概述

小型赛事运营后台，解决报名管理、组别调整、号码布发放、现场检录、退赛记录等环节靠人工临时同步导致比赛当天混乱的问题。目标用户为赛事运营人员、检录台志愿者、物料发放人员和裁判长，核心价值是用一个界面让所有角色实时同步选手状态，减少现场沟通成本和出错率。

## 2. 核心功能

### 2.1 用户角色

| 角色 | 使用场景 | 核心权限 |
|------|----------|----------|
| 运营人员 | 统筹报名、分组、异常处理 | 全部操作权限 |
| 检录台志愿者 | 按号码或姓名快速核验选手 | 检录标记、异常上报 |
| 物料人员 | 标记号码布发放状态 | 号码布发放标记 |
| 裁判长 | 查看未检录名单、组别冲突 | 只读查看 + 异常确认 |

### 2.2 功能模块

1. **总览仪表盘**: 关键指标、待处理事项、实时状态
2. **报名名单**: 全量报名数据、搜索筛选、状态标记
3. **分组管理**: 组别调整、冲突检测、候补转正
4. **号码布发放**: 发放标记、批量操作、未发放提醒
5. **现场检录**: 号码/姓名快速核验、异常处理、实时状态
6. **退赛记录**: 退赛登记、原因记录、统计汇总

## 3. 核心流程

### 3.1 检录流程
志愿者在检录台输入选手号码或姓名 → 系统匹配选手 → 核对信息 → 正常则标记已检录 → 异常则选择异常类型并登记

### 3.2 号码布发放流程
物料人员查看未发放列表 → 找到选手 → 核对身份 → 标记已发放

### 3.3 退赛流程
运营人员收到退赛请求 → 在退赛记录中登记 → 系统自动更新选手状态

```mermaid

    "选手到场" --> "检录台输入号码/姓名"
    "检录台输入号码/姓名" --> "系统匹配"
    "系统匹配" --> "找到选手"
    "系统匹配" --> "未找到 → 异常登记"
    "找到选手" --> "信息核验"
    "信息核验" --> "一致 → 标记已检录"
    "信息核验" --> "证件不符 → 异常登记"
    "信息核验" --> "临时退赛 → 退赛登记"
```

## 4. 界面设计

### 4.1 设计风格

- **主色调**: 深灰底色（#1a1a2e）+ 橙色强调色（#f97316），工业实用风格
- **辅色调**: 绿色（已检录/已完成）、红色（异常/退赛）、黄色（待处理/候补）
- **按钮风格**: 紧凑型，圆角小，主要操作用填充色，次要操作用描边
- **字体**: 等宽字体用于号码显示，无衬线字体用于正文，标题用粗体大号
- **布局风格**: 左侧固定窄导航栏 + 顶部搜索栏 + 右侧主内容区，信息密度优先
- **图标**: 使用 lucide-react 图标库，紧凑线条风格

### 4.2 页面设计概览

| 页面名称 | 模块名称 | UI 要素 |
|----------|----------|---------|
| 总览仪表盘 | 指标卡片 | 4列网格，数字大号加粗，背景深灰，状态色边框 |
| 总览仪表盘 | 异常列表 | 紧凑表格，红色/黄色左侧边框标识严重程度 |
| 报名名单 | 搜索栏 | 顶部固定，输入框+下拉筛选器 |
| 报名名单 | 选手表格 | 紧凑行高，状态用色点标记，操作按钮右对齐 |
| 分组管理 | 组别卡片 | 左侧组别列表，右侧该组选手 |
| 号码布发放 | 发放表格 | 号码列加宽等宽字体，状态切换用开关 |
| 现场检录 | 搜索框 | 居中大号输入框，回车即检录，F2快捷键 |
| 现场检录 | 选手信息卡 | 搜索后弹出，信息突出显示组别和号码 |
| 退赛记录 | 登记表单 | 右侧抽屉弹出，选手搜索+原因选择 |

### 4.3 响应式设计

- 桌面优先，最小适配 1280px 宽度笔记本屏幕
- 侧边栏可折叠以增加内容区宽度
- 表格在小屏下隐藏次要列
- 检录页面支持键盘快捷操作（Enter确认、Esc取消、Tab切换字段）

## 5. Mock 数据要求

- 亲子组选手 8-10 人（含 1 名证件不符异常）
- 公开组选手 12-15 人（含 2 名重复报名）
- 企业团体 3 支队伍，每队 4-5 人
- 候补选手 3-4 人
- 退赛记录 2-3 条
- 已发放号码布约 60%，已检录约 40%
- 组别冲突 1-2 条（同一选手出现在两个组别）

# 《音乐培训机构-考级曲目与练习计划》系统 - 实现说明

## 一、项目概述

本系统旨在解决音乐培训机构考级曲目与练习计划管理中的核心痛点：信息分散、状态追踪困难、角色协同效率低。系统采用前后端分离架构，通过统一的状态机驱动，实现完整的业务流程闭环。

---

## 二、核心功能实现

### 2.1 角色化待办视图

| 角色 | 待办状态 | 功能权限 |
|------|----------|----------|
| **教务老师(Admin)** | 已提交、审核中、已完成 | 审核通过、退回修改、确认考级结果 |
| **任课老师(Teacher)** | 草稿、已退回、练习中 | 创建记录、提交审核、更新进度、补充修改、标记完成 |
| **家长顾问(Consultant)** | 练习中、已完成 | 查看详情、查看操作日志 |

### 2.2 状态流转机制

系统采用状态机模式管理记录生命周期，确保状态转换的合法性：

```
草稿 → 已提交 → 审核中 → 已通过 → 练习中 → 已完成 → 考级通过/未通过
            ↓            ↓           ↓
           退回 ←────── 补充 ←────── 重新练习
```

### 2.3 统一记录模型

考级曲目记录包含以下核心信息：
- **基本信息**：学员姓名、乐器、考级级别、曲目名称
- **练习计划**：计划周期、每日练习目标、本周重点、进度追踪
- **状态信息**：当前状态、退回原因（如有）、补充备注（如有）
- **操作日志**：完整记录所有操作历史

## 三、权限简化说明

### 3.1 当前实现

- **基于角色的访问控制(RBAC)**：通过请求头 `x-role` 标识用户角色
- **数据隔离**：任课老师只能查看和操作自己创建的记录
- **操作权限**：根据角色和当前状态动态显示可执行操作

### 3.2 简化点

1. **简化认证**：暂未实现完整的用户认证体系，通过请求头模拟角色身份
2. **简化授权**：未实现细粒度的资源级权限控制，仅基于角色过滤
3. **简化会话管理**：无登录状态保持，刷新页面后角色重置为默认值

### 3.3 后续扩展建议

- 集成 JWT/OAuth2 认证
- 实现基于策略的权限控制
- 添加操作审计日志

## 四、附件功能简化说明

### 4.1 当前实现

- **无附件上传功能**：系统暂不支持上传乐谱、录音等附件
- **纯文本记录**：退回原因和补充备注仅支持文本格式

### 4.2 简化原因

1. **核心需求优先**：先保证主链路（状态流转、待办视图）能跑通
2. **复杂度控制**：附件管理涉及存储、预览、下载等多个环节
3. **资源限制**：需额外配置文件存储服务（如 AWS S3、阿里云 OSS）

### 4.3 后续扩展建议

- 支持乐谱图片、练习录音上传
- 集成云存储服务
- 添加附件预览和下载功能

---

## 五、通知功能简化说明

### 5.1 当前实现

- **无主动通知**：状态变更时不主动推送通知
- **被动刷新**：用户需手动刷新页面获取最新状态

### 5.2 简化原因

1. **实时性要求不高**：考级准备周期较长，非即时协作场景
2. **实现复杂度**：需集成消息队列、WebSocket 等技术
3. **用户体验权衡**：当前手动刷新可满足基本需求

### 5.3 后续扩展建议

- 实现 WebSocket 实时推送
- 集成邮件/短信通知
- 添加站内消息中心

## 六、外部系统集成简化说明

### 6.1 当前实现

- **独立运行**：系统作为独立应用，不依赖其他外部系统
- **本地数据库**：使用 SQLite 本地数据库存储数据
- **无数据同步**：不与学员管理系统、财务系统等集成

### 6.2 简化原因

1. **快速落地**：避免与其他系统的耦合，降低部署复杂度
2. **数据独立性**：保证核心业务数据的完整性和一致性
3. **接口标准化**：提供 RESTful API，便于后续集成

### 6.3 后续扩展建议

- 与学员管理系统对接（获取学员信息）
- 与教务排课系统集成（关联课程安排）
- 与考级机构系统对接（同步考级结果）

## 七、前后端边界清晰化

### 7.1 前端职责

| 职责 | 说明 |
|------|------|
| 角色身份识别 | 根据请求头识别当前用户角色 |
| 待办列表筛选 | 根据角色过滤显示对应的待办记录 |
| 详情展示 | 渲染记录详情、练习计划、操作日志 |
| 操作交互 | 表单校验、状态变更触发、弹窗交互 |

### 7.2 后端职责

| 职责 | 说明 |
|------|------|
| 用户认证 | 验证用户身份和角色（简化版） |
| 状态流转控制 | 严格遵循状态机规则，拒绝非法状态转换 |
| 权限校验 | 根据角色判断是否允许执行操作 |
| 操作日志记录 | 每次状态变更自动记录操作日志 |
| 数据持久化 | 负责数据库的读写操作 |

### 7.3 状态管理策略

- **前端**：仅管理 UI 状态（弹窗显示、表单数据）
- **后端**：管理业务状态（记录状态、操作日志）
- **数据同步**：操作完成后刷新列表获取最新状态

# 税务咨询机构-风险提示与后续跟踪系统

## 1. 产品概述

为税务咨询机构打造的风险提示与后续跟踪管理平台，解决政策适用争议、底稿版本混乱、答复无人签收等常见问题。通过统一的操作日志和待办跟踪机制，确保税务顾问、项目经理、客户财务三方信息同步，消除信息孤岛。

系统核心价值：让每个风险提示都能追踪到底，每个待办都能找到责任人。

## 2. 核心功能

### 2.1 用户角色

| 角色 | 职责 | 核心待办 |
|------|------|----------|
| 税务顾问 | 政策解读、底稿编制、风险评估 | 待回复的咨询工单、待处理的风险提示、待签收的答复 |
| 项目经理 | 项目统筹、质量把控、客户沟通 | 待审核的底稿、待确认的政策适用、待跟踪的争议 |
| 客户财务 | 资料提供、方案确认、反馈评价 | 待补充的资料、待签收的答复、待确认的申报方案 |

### 2.2 核心业务流程

```
[咨询工单/政策资料/申报底稿]
         ↓
[风险识别] → [风险提示记录创建]
         ↓
[指派处理人] → [待办通知]
         ↓
[风险处理] → [退回/补充/确认]
         ↓
[结果签收] → [流程关闭]
         ↓
[后续跟踪] → [完成/升级]
```

### 2.3 风险类型分类

1. **政策适用争议**：对税收政策理解不一致，需要进一步明确
2. **底稿版本混乱**：多个版本并存，需要统一版本管理
3. **答复未签收**：发出的答复长时间未被客户确认
4. **补充资料缺失**：缺少必要的财务资料或凭证
5. **申报期限风险**：申报时间紧迫，需要加速处理
6. **系统操作异常**：系统问题导致工单处理延误

## 3. 功能模块

### 3.1 风险提示管理

- **风险识别**：从咨询工单、政策资料、申报底稿中自动或手动识别风险
- **风险分级**：
  - 🔴 高风险：影响申报合规性或期限
  - 🟡 中风险：需要协调沟通
  - 🟢 低风险：优化建议
- **风险详情**：包含原始工单信息、政策依据、处理过程、备注记录
- **操作日志**：完整记录所有处理动作、时间、操作人

### 3.2 待办管理

- **角色视图**：税务顾问/项目经理/客户财务各自独立的待办列表
- **待办筛选**：
  - 按状态：待处理、处理中、待确认、已完成
  - 按类型：风险提示、退回工单、待签收答复
  - 按紧急度：高、中、低
  - 按时间：今日到期、本周到期、已逾期
- **批量操作**：支持批量标记、批量转派

### 3.3 后续跟踪

- **跟踪周期**：可设置7天/15天/30天自动提醒
- **跟踪记录**：每次跟踪的结果、备注、下一步动作
- **升级机制**：超过跟踪周期未解决，自动升级通知

### 3.4 信息整合视图

单条记录整合：
- 风险提示详情
- 后续跟踪记录
- 退回原因（如果有）
- 补充备注（如果需要）
- 完整操作日志
- 相关工单/资料链接

## 4. 页面清单

### 4.1 登录/角色切换页
- 简化登录：输入工号即可（实际生产环境可对接AD/LDAP）
- 角色切换：支持同时拥有多角色时快速切换

### 4.2 仪表盘首页

- 快捷入口：新建风险提示、查看全部待办

### 4.3 风险提示列表页
- 多维度筛选：角色、状态、类型、紧急度、时间范围
- 列表字段：编号、类型、紧急度、关联工单、责任人、状态、更新时间
- 批量操作：标记已处理、转派责任人
- 快速查看：鼠标悬停显示关键信息

### 4.4 风险提示详情页
- **基础信息区**：
  - 风险编号、类型、紧急度

- **处理进度区**：
  - 当前状态、处理阶段
  - 当前责任人
  - 下一步动作建议
- **处理记录区**：
  - 操作日志（时间、操作人、动作、结果）
  - 退回原因（如有）
  - 补充备注（如有）
- **后续跟踪区**：
  - 跟踪周期设置
  - 跟踪记录列表
  - 下次跟踪时间
- **操作区**：
  - 处理动作：确认处理/退回/升级
  - 填写备注
  - 更新状态
  - 通知相关人

### 4.5 统计报表页
- 风险提示趋势图
- 各角色处理效率对比
- 高频风险类型分析
- 超时未处理工单统计

## 5. 核心流程说明

### 5.1 风险提示创建流程

```
1. 从工单/资料页面发起 → 填写风险信息 → 选择紧急度 → 提交
2. 系统自动识别 → 生成风险提示 → 通知责任人
3. 责任人接收 → 查看详情 → 开始处理
```

### 5.2 处理完成流程

```
1. 责任人处理 → 添加处理记录 → 更新状态
2. 如需客户确认 → 发送签收请求
3. 客户查看处理结果 → 确认签收/提出异议
4. 全部确认 → 标记完成 → 安排后续跟踪
5. 跟踪周期结束 → 无异常 → 流程关闭
```

### 5.3 退回处理流程

```
1. 处理中发现问题 → 填写退回原因 → 选择退回对象
2. 退回对象接收通知 → 查看退回原因 → 补充/修正
3. 重新提交 → 继续处理流程
```

## 6. 样例数据场景

### 场景1：政策适用争议
- 风险类型：政策适用争议
- 关联工单：2024-个税-001（某科技公司股权激励个税计算）
- 争议焦点：股权激励行权时点的个人所得税计算方法
- 处理过程：
  - 税务顾问A提出两种计算方案
  - 项目经理B组织内部讨论
  - 客户财务C提供历史数据
  - 最终确定采用方案B
- 退回原因：无
- 补充备注：需在申报前完成最终确认

### 场景2：底稿版本混乱
- 风险类型：底稿版本混乱
- 关联资料：2024-企税-015（某制造企业研发费用加计扣除）
- 问题描述：同一项目出现v1.2、v1.3、v2.0三个版本
- 处理过程：
  - 项目经理发现版本混乱
  - 发起版本确认请求
  - 税务顾问核对后确认v2.0为最终版本
  - 通知客户财务确认签收
- 退回原因：需客户提供最终审计报告
- 补充备注：客户已承诺下周一前提供

### 场景3：答复未签收
- 风险类型：答复未签收
- 关联工单：2024-增值-003（某商场增值税进项抵扣咨询）
- 问题描述：答复发出5天后客户仍未签收确认
- 处理过程：
  - 系统自动检测到未签收
  - 再次发送签收提醒
  - 客户仍未响应
  - 项目经理电话联系客户财务
  - 客户确认已阅，知悉处理结果
- 退回原因：无
- 补充备注：客户确认口头知晓，需补签书面确认

## 7. 技术约束

- **前端框架**：SvelteKit
- **后端数据库**：SQLite（轻量级、易部署）
- **认证方式**：简化登录（工号+简单密码，实际可对接企业AD）
- **数据持久化**：所有数据必须存入SQLite，不能仅存在于页面内存
- **操作日志**：所有数据变更必须记录操作日志，包含操作人、时间、动作、变更前后值

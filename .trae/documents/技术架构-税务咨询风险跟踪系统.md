### 1.2 技术栈

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 前端框架 | SvelteKit | 服务端渲染 + 客户端路由 |
| UI组件 | 原生 Svelte + TailwindCSS | 自定义组件，简洁高效 |
| 状态管理 | SvelteKit stores | 轻量级状态管理 |
| 后端 | SvelteKit API Routes | 服务端函数处理业务逻辑 |
| 数据库 | SQLite + better-sqlite3 | 轻量级、易部署、无需独立服务 |
| 认证 | Session-based | 简化版认证，支持角色切换 |

### 2.2 数据库表结构

#### users 表
```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT UNIQUE NOT NULL,
    password TEXT NOT NULL,
    role TEXT NOT NULL CHECK(role IN ('tax_advisor', 'project_manager', 'client_finance')),
    name TEXT NOT NULL,
    email TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

#### risk_alerts 表
```sql
CREATE TABLE risk_alerts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    code TEXT UNIQUE NOT NULL,
    title TEXT NOT NULL,
    type TEXT NOT NULL CHECK(type IN (
        'policy_dispute',      -- 政策适用争议
        'draft_version_chaos',  -- 底稿版本混乱
        'response_unsigned',   -- 答复未签收
        'missing_docs',         -- 补充资料缺失
        'deadline_risk',        -- 申报期限风险
        'system_error'          -- 系统操作异常
    )),
    severity TEXT NOT NULL CHECK(severity IN ('high', 'medium', 'low')),
    status TEXT NOT NULL DEFAULT 'pending' CHECK(status IN (
        'pending',      -- 待处理
        'processing',  -- 处理中
        'confirming',  -- 待确认
        'completed',   -- 已完成
        'closed'       -- 已关闭
    )),
    assignee_id INTEGER REFERENCES users(id),
    creator_id INTEGER REFERENCES users(id),
    related_type TEXT CHECK(related_type IN ('consult', 'policy', 'draft')),
    related_id TEXT,
    reject_reason TEXT,
    supplement_note TEXT,
    due_date DATETIME,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

#### todo_items 表
```sql
CREATE TABLE todo_items (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    risk_alert_id INTEGER REFERENCES risk_alerts(id),
    user_id INTEGER REFERENCES users(id),
    todo_type TEXT NOT NULL CHECK(todo_type IN (
        'risk_process',     -- 风险处理
        'review_confirm',   -- 审核确认
        'sign_receive',     -- 签收确认
        'supplement_docs',  -- 补充资料
        'follow_up'          -- 后续跟踪
    )),
    status TEXT NOT NULL DEFAULT 'pending' CHECK(status IN ('pending', 'processing', 'completed')),
    priority TEXT CHECK(priority IN ('high', 'medium', 'low')),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

#### follow_ups 表
```sql
CREATE TABLE follow_ups (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    risk_alert_id INTEGER REFERENCES risk_alerts(id),
    follow_date DATETIME NOT NULL,
    result TEXT NOT NULL CHECK(result IN ('resolved', 'pending', 'escalated')),
    note TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

#### operation_logs 表
```sql
CREATE TABLE operation_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    risk_alert_id INTEGER REFERENCES risk_alerts(id),
    user_id INTEGER REFERENCES users(id),
    action TEXT NOT NULL,
    description TEXT,
    old_value TEXT,
    new_value TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

## 3. API路由定义

### 3.1 认证相关

| 路由 | 方法 | 说明 | 请求体 | 响应 |
|------|------|------|--------|------|
| `/api/auth/login` | POST | 用户登录 | `{username, password}` | `{success, user, role}` |
| `/api/auth/logout` | POST | 用户登出 | - | `{success}` |
| `/api/auth/switch-role` | POST | 切换角色 | `{role}` | `{success, user}` |
| `/api/auth/current-user` | GET | 获取当前用户 | - | `{user}` |

### 3.2 风险提示相关

| 路由 | 方法 | 说明 | 请求体 | 响应 |
|------|------|------|--------|------|
| `/api/risk-alerts` | GET | 获取风险提示列表 | Query: `{status?, type?, severity?, assignee?, page, limit}` | `{data: [], total, page}` |
| `/api/risk-alerts` | POST | 创建风险提示 | `{title, type, severity, assignee_id, related_type, related_id, due_date}` | `{id, code}` |
| `/api/risk-alerts/:id` | GET | 获取风险提示详情 | - | `{riskAlert, todos, followUps, operationLogs}` |
| `/api/risk-alerts/:id` | PUT | 更新风险提示 | `{status, reject_reason?, supplement_note?, assignee_id?}` | `{success}` |
| `/api/risk-alerts/:id/process` | POST | 处理风险提示 | `{action, description}` | `{success, logId}` |

### 3.3 待办事项相关

| 路由 | 方法 | 说明 | 请求体 | 响应 |
|------|------|------|--------|------|
| `/api/todos` | GET | 获取待办列表 | Query: `{user_id?, status?, type?}` | `{data: []}` |
| `/api/todos` | POST | 创建待办 | `{risk_alert_id, user_id, todo_type, priority}` | `{id}` |
| `/api/todos/:id` | PUT | 更新待办 | `{status}` | `{success}` |
| `/api/todos/:id/complete` | POST | 完成待办 | `{note?}` | `{success}` |

### 3.4 后续跟踪相关

| 路由 | 方法 | 说明 | 请求体 | 响应 |
|------|------|------|--------|------|
| `/api/risk-alerts/:id/follow-ups` | GET | 获取跟踪记录 | - | `{data: []}` |
| `/api/risk-alerts/:id/follow-ups` | POST | 添加跟踪记录 | `{follow_date, result, note}` | `{id}` |
| `/api/risk-alerts/:id/follow-ups/:followUpId` | PUT | 更新跟踪记录 | `{result?, note?}` | `{success}` |

### 3.5 统计相关

| 路由 | 方法 | 说明 | 响应 |
|------|------|------|------|
| `/api/dashboard/stats` | GET | 获取仪表盘统计 | `{total, pending, processing, completed, bySeverity, byType}` |
| `/api/dashboard/my-todos` | GET | 获取当前用户待办 | `{data: []}` |

## 6. 核心业务流程实现

### 6.1 风险提示创建
```typescript
// 1. 创建风险提示记录
// 2. 自动生成唯一编号（格式：RF-YYYYMMDD-序号）
// 3. 根据 assignee 创建待办事项
// 4. 记录操作日志（创建）
```

### 6.2 风险提示处理
```typescript
// 1. 更新风险提示状态
// 2. 可选填写退回原因或补充备注
// 3. 如果是退回操作，创建新的待办给退回对象
// 4. 记录操作日志（状态变更、处理动作）
```

### 6.3 后续跟踪
```typescript
// 1. 在风险提示详情页添加跟踪记录
// 2. 记录跟踪日期、结果、备注
// 3. 根据结果更新风险提示状态
// 4. 如果是升级结果，通知相关人员
```

### 6.4 待办联动
```typescript
// 1. 风险提示状态变更时，自动创建/更新相关待办
// 2. 待办完成时，更新风险提示状态
// 3. 仪表盘实时显示各角色待办数量
```

## 8. 安全考虑

- 密码使用bcrypt加密存储
- Session存储在HTTP-only Cookie中
- API路由需要验证用户登录状态
- 所有数据库操作使用参数化查询，防止SQL注入
- 操作日志记录所有敏感操作，便于审计

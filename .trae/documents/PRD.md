# 司法鉴定所-委托受理与材料核验系统

## 1. 项目概述

### 1.1 项目背景
当前司法鉴定所的信息散在委托书、样本流转和鉴定意见书里，缺乏完整的审计链条。受理员、鉴定人、质控审核之间的交接需要明确的先后顺序和完整的操作记录。

### 1.2 项目目标
构建一个完整的委托受理与材料核验系统，确保：
- **业务责任不简化**：每个环节都有明确的负责人和时间戳
- **信息链完整性**：从委托受理到材料核验，每一步都留痕
- **异常处理能力**：支持缺材料、超时、复核不通过等异常单的处理
- **可追溯性**：任意时刻可以追溯完整的业务流程

### 1.3 核心原则
- 可以简化外部系统的集成
- 不能简化业务责任和审计追踪
- 数据必须能够"拼成一条线"

## 2. 用户角色

| 角色 | 职责 | 权限范围 |
|------|------|---------|
| **受理员 (Acceptor)** | 接收委托、录入基本信息、初始材料收集 | 委托受理、材料补充通知 |
| **鉴定人 (Appraiser)** | 材料核验、样本流转记录、鉴定意见出具 | 材料核验、状态更新、样本管理 |
| **质控审核 (QC Reviewer)** | 质量控制、审核不通过处理、流程监督 | 全流程审核、异常单处理 |
| **系统管理员 (Admin)** | 账号管理、演示数据初始化 | 系统配置 |

## 3. 核心业务流程

### 3.1 委托受理流程

```
[委托方提交] 
    ↓
[受理员接收委托] 
    ↓ 创建委托单，记录操作人、操作时间
[录入基本信息]
    - 委托方信息
    - 案件类型
    - 鉴定项目
    - 预计完成时间
    ↓
[材料初步核查]
    - 检查委托材料清单
    - 标记缺材料情况（如果存在）
    ↓
[委托受理完成] → 状态变更为"材料核验中"
```

### 3.2 材料核验流程

```
[接收委托单]
    ↓
[逐项核验材料]
    - 身份证明
    - 委托书
    - 相关证据材料
    - 其他必要文件
    ↓
[核验结果判定]
    ├── 全部合格 → [核验通过] → 状态更新
    ├── 部分缺失 → [材料不全] → 通知委托方补充
    └── 不合格 → [核验不通过] → 退回修改
    ↓
[质控审核]
```

### 3.3 质控审核流程

```
[接收核验完成的委托单]
    ↓
[质量审核]
    ├── 合格 → [审核通过] → 进入鉴定阶段
    ├── 不合格 → [审核不通过] → 返回鉴定人重新处理
    └── 超时预警 → [超时处理] → 记录超时原因
    ↓
[流程完成]
```

## 4. 状态流转设计

### 4.1 委托单状态

```
PENDING_ACCEPTANCE (待受理)
    ↓ 受理员提交
ACCEPTANCE_IN_PROGRESS (受理中)
    ↓ 受理员完成受理
MATERIAL_VERIFICATION (材料核验中)
    ↓ 鉴定人核验
VERIFICATION_PASSED (核验通过)
VERIFICATION_FAILED (核验不通过) ← 异常单
MATERIAL_INCOMPLETE (材料不全) ← 异常单
    ↓ 质控审核
QC_REVIEW_PENDING (待质控审核)
    ↓ 质控审核
QC_APPROVED (审核通过)
QC_REJECTED (审核不通过) ← 异常单
    ↓
COMPLETED (已完成)
ON_HOLD (暂停/超时) ← 异常单
```

### 4.2 状态流转规则

1. **严格顺序性**：状态必须按照预定顺序流转，不可跳级
2. **操作留痕**：每次状态变更必须记录操作人、时间、备注
3. **回退机制**：支持异常情况下的状态回退（需授权）
4. **超时监控**：自动记录超时节点，生成预警

   - 快捷查看异常单（缺材料、超时、复核不通过）

   - 完整的业务信息展示

4. **材料补充**
   - 缺材料通知发送记录
   - 补充材料接收
   - 补充材料核验

### 5.3 材料核验模块

**功能描述**：鉴定人对委托材料进行核验

**核心功能**：
1. **核验工作台**
   - 待核验委托单队列
   - 快速核验操作
   - 核验进度统计

2. **材料核验**
   - 逐项核验材料
   - 核验结果记录（通过/不通过）
   - 问题材料标注
   - 核验意见填写

3. **核验记录**
   - 核验历史
   - 核验人签名
   - 核验时间戳

4. **异常标记**
   - 缺材料标记
   - 材料不合格标记
   - 超时提醒

### 5.4 状态流转与审计模块

**功能描述**：完整的流程控制和审计追踪

**核心功能**：
1. **状态流转控制**
   - 当前状态展示
   - 可执行操作展示
   - 状态变更审批（需要时）
   - 状态回退（异常情况）

   - 时间节点标记

4. **统计分析**

   - 处理时效统计
   - 异常单占比
   - 超时统计

## 6. 异常单处理

### 6.1 缺材料异常

**场景描述**：委托方提交的材料不完整

**处理流程**：
1. 鉴定人核验时发现缺材料
2. 系统标记为"材料不全"状态
3. 自动通知受理员
4. 受理员联系委托方补充材料
5. 材料补充后重新核验
6. 核验通过后继续流程

**数据记录**：
- 缺少材料清单
- 通知时间
- 补充材料截止时间
- 补充材料记录

### 6.2 超时异常

**场景描述**：委托单处理超过预定时间

**处理流程**：
1. 系统自动检测超时
2. 标记为"暂停/超时"状态
3. 记录超时原因
4. 通知责任人
5. 人工介入处理
6. 处理完成后恢复正常流程

**数据记录**：
- 超时开始时间
- 超时时长
- 超时原因
- 处理措施

### 6.3 复核不通过异常

**场景描述**：质控审核发现问题，需要返回修改

**处理流程**：
1. 质控审核发现不合格
2. 标记为"审核不通过"状态
3. 填写不通过原因
4. 返回鉴定人重新处理
5. 重新提交审核
6. 审核通过后继续流程

**数据记录**：
- 审核不通过时间
- 不通过原因
- 修改要求
- 重新审核记录

## 8. 数据结构设计

### 8.1 委托单 (Delegation)

```
{
  id: string,
  delegationNumber: string,        // 委托单号
  status: enum,                   // 状态
  applicantInfo: {
    name: string,
    organization: string,
    contact: string,
    idCard: string
  },
  caseInfo: {
    type: string,                  // 案件类型
    description: string,           // 案件描述
    incidentDate: date,            // 事发日期
    location: string               // 事发地点
  },
  appraisalItems: string[],       // 鉴定项目
  expectedCompletionDate: date,    // 预计完成日期
  materials: [{
    name: string,
    required: boolean,
    provided: boolean,
    verificationStatus: enum,
    notes: string
  }],
  currentAssignee: string,        // 当前责任人
  createdBy: string,              // 创建人
  createdAt: datetime,            // 创建时间
  updatedAt: datetime,             // 更新时间
  completionDate: datetime,       // 完成时间
  isAbnormal: boolean,             // 是否异常
  abnormalType: string,           // 异常类型
  abnormalReason: string           // 异常原因
}
```

### 8.2 审计日志 (AuditLog)

```
{
  id: string,
  delegationId: string,           // 关联委托单
  action: enum,                   // 操作类型

  operateTime: datetime,          // 操作时间

  details: object                 // 详细操作数据
```

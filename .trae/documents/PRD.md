# 翻译公司译员分配与术语维护系统 - 产品需求文档

## 1. 产品概述
翻译公司内部译员分配与术语维护管理系统，解决项目经理、译员、审校之间的协作流程问题，确保每个环节的操作留痕、状态变更可追溯，避免依赖口头沟通和翻找旧台账。

核心价值：将翻译工作流从"口头解释+翻找记录"转变为"系统留痕+状态驱动"，让驳回、补录等操作有迹可循。

## 2. 核心功能

### 2.1 用户角色
| 角色 | 核心权限 |
|------|---------|
| 项目经理 | 创建译员分配、查看状态、驳回/通过术语维护、批量操作 |
| 译员 | 接收分配、提交译稿、维护术语、查看历史备注 |
| 审校 | 审核译稿、确认术语维护、驳回补录 |

### 2.2 功能模块
1. **工作台首页**：状态看板、快捷操作入口、待办事项列表
2. **译员分配页**：分配列表、批量操作、状态标签、详情查看
3. **术语维护页**：术语列表、回看历史、驳回/补录操作、备注记录
4. **详情页**：完整流程展示、操作历史时间线、状态流转记录

### 2.3 页面详情
| 页面名称 | 模块名称 | 功能描述 |
|---------|---------|---------|
| 工作台首页 | 状态看板 | 显示各状态任务数量统计（待分配/进行中/待审核/已完成） |
| 工作台首页 | 待办列表 | 按优先级展示当前用户的待办任务，支持快速跳转 |
| 译员分配页 | 分配列表 | 表格展示所有译员分配记录，支持筛选、搜索、排序 |
| 译员分配页 | 批量操作 | 批量分配、批量驳回、批量通过等操作 |
| 译员分配页 | 状态标签 | 可视化状态标签（待分配/已分配/进行中/已完成/已驳回） |
| 术语维护页 | 术语列表 | 展示术语维护记录，关联译员分配信息 |
| 术语维护页 | 回看功能 | 查看术语维护历史版本和操作记录 |
| 术语维护页 | 驳回/补录 | 实际的驳回和补录操作，非仅提示文案 |

| 详情页 | 操作历史 | 时间线展示所有操作记录，包含操作人、时间、备注 |
| 详情页 | 状态流转 | 当前状态、可执行操作、下一步流转方向 |

## 3. 核心流程

### 3.1 主流程描述
项目经理创建译员分配 → 译员接收并开始工作 → 译员提交译稿并维护术语 → 审校审核译稿 → 审校确认/驳回术语维护 → 项目经理验收 → 完成

每个环节的操作都需要留痕：谁在什么时间做了什么操作，添加了什么备注。

### 3.3 状态定义
- **待分配**：任务已创建，等待项目经理分配译员
- **已分配**：已分配译员，等待译员接收
- **进行中**：译员已接收，正在工作中
- **待审核**：译员已提交，等待审校审核
- **已驳回**：审校驳回，需要译员修改
- **已完成**：流程结束，任务完成

## 4. 用户界面设计

### 4.1 设计风格
- **主色调**：专业蓝（#1E40AF）+ 警示橙（#F59E0B）用于驳回状态
- **辅助色**：成功绿（#10B981）、中性灰（#6B7280）
- **按钮风格**：圆角矩形按钮，主要操作使用实心色，次要操作使用描边
- **字体**：思源黑体 / PingFang SC，标题 18px 加粗，正文 14px
- **布局风格**：左侧导航栏 + 右侧内容区，卡片式布局
- **图标**：线性图标风格，统一 2px 描边

### 4.2 页面设计概览
| 页面名称 | 模块名称 | UI元素 |
|---------|---------|--------|
| 工作台首页 | 状态看板 | 4个统计卡片，不同颜色区分状态，数字突出显示 |
| 工作台首页 | 待办列表 | 列表形式，每项显示任务名称、状态标签、截止时间、快捷操作按钮 |
| 译员分配页 | 分配列表 | 数据表格，包含复选框、任务名称、译员、状态、操作列 |
| 译员分配页 | 批量操作栏 | 固定在表格上方，包含批量分配、批量驳回、批量通过按钮 |
| 术语维护页 | 术语列表 | 卡片式列表，每张卡片显示术语原文、译文、状态、操作按钮 |
| 术语维护页 | 回看弹窗 | 模态框展示历史版本，时间线形式展示变更记录 |
| 详情页 | 流程图示 | 横向流程图，当前节点高亮，已完成节点打勾 |
| 详情页 | 操作历史 | 垂直时间线，每条记录显示操作人头像、操作内容、时间、备注 |

### 4.3 响应式设计
- 桌面优先设计，最小支持 1280px 宽度
- 表格在小屏幕下支持横向滚动
- 移动端适配：导航栏收起为汉堡菜单，表格转为卡片列表

### 4.4 交互细节
- 状态标签使用不同颜色和图标区分
- 驳回操作需要填写驳回原因（必填）
- 补录操作需要填写补录说明
- 所有操作都有确认弹窗，防止误操作
- 操作成功后显示 Toast 提示

## 5. 样例数据要求

系统需要预置以下样例数据，用于演示完整流程：

### 5.1 译员分配样例
1. **已完成样例**：包含完整的分配→审核→确认流程，有多次驳回和补录记录
2. **进行中样例**：译员正在工作中，有历史备注
3. **待审核样例**：译员已提交，等待审校审核，有术语维护记录
4. **已驳回样例**：审校驳回，有驳回原因和修改建议

### 5.2 术语维护样例
每个样例至少包含：
- 术语原文和译文
- 维护历史（至少2个版本）
- 操作记录（谁在什么时候做了什么）
- 备注说明

### 5.3 操作历史样例
每个样例至少包含5条操作记录：
- 项目经理创建分配
- 译员接收任务
- 译员提交译稿
- 审校驳回（附原因）
- 译员修改并重新提交
- 审校确认通过

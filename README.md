# KTV门店管理系统 - 储值消费与退款审核

## 项目说明

这是一个真实业务场景下的KTV门店内部管理系统，实现了从**前台开单 -> 储值消费 -> 异常上报 -> 处理人员跟进 -> 店长退款审核**的完整业务链路。

## 核心特点

1. **三角色接力流程**：前台 → 处理人员 → 店长，每个角色有独立的工作台和菜单
2. **数据全链路打通**：Mock数据、退款审核回看、储值消费处理、空状态都已串联
3. **真实业务场景**：预置了包厢撞档、酒水赠送纠纷等异常样例，可以直接触发提醒和退回
4. **储值消费不是终点**：结账后可以继续发起退款申请
5. **退款审核不是独立菜单**：从异常处理流程自然流转到退款审核

## 角色与功能

### 1. 前台（Reception）
- **开单入场**：选择包厢、关联会员、快速开单
- **消费中订单**：查看当前正在消费的订单
- **结账离场**：添加酒水小吃、设置赠送、储值抵扣、完成结账
- **异常上报**：遇到问题直接上报异常（包厢撞档、酒水纠纷、会员账不清等）

### 2. 处理人员（Handler）
- **待处理异常**：查看前台上报的异常，进行处理
- **退款申请**：处理异常时可以发起退款申请，也可以对已完成订单单独退款
- **处理记录**：查看所有处理过的工单，带时间线展示

### 3. 店长（Manager）
- **退款审核**：审核处理人员提交的退款申请，可以通过或拒绝
- **数据回看**：查看所有退款记录、异常历史、订单全量数据
- **会员管理**：查看会员列表、为会员充值
- **经营统计**：查看订单、营业额、异常分布等统计数据

## 快速测试主链路

### 路径1：正常消费流程
```
前台开单 → 添加酒水 → 结账（可选储值抵扣） → 订单完成
```

### 路径2：异常处理 + 退款流程（完整链路）
```
前台遇到问题 → 上报异常（选类型、写描述）
    ↓
处理人员看到待处理列表 → 查看详情 → 写处理意见 → 选择是否退款
    ↓
如果需要退款 → 填写退款金额和原因 → 提交店长审核
    ↓
店长看到待审核列表 → 查看详情（含异常描述、处理意见）
    ↓
店长审核：
  ├─ 通过 → 款项退回会员储值账户 → 订单状态更新为「已退款」
  └─ 拒绝 → 写明原因 → 订单状态更新为「已拒绝」
```

## 启动项目

```bash
# 安装依赖
npm install

# 启动开发服务器
npm run dev
```

项目启动后访问 http://localhost:3000

## 角色切换方法

点击右上角的用户头像下拉菜单，可以在三个角色之间切换：
- 前台小王
- 处理员小张  
- 店长陈经理

每个角色切换后，左侧菜单和数据都会相应变化。

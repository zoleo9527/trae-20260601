# 口腔耗材商 - 客户资质与采购申请管理系统

用于替代口腔耗材商旧台账、现场记录和沟通截图中的反复确认流程，核心解决客户资质与采购申请之间责任不清的问题。

## 启动方式

```bash
# 安装依赖
npm install

# 启动开发服务器（前端 + 后端同时启动）
npm run dev
```

前端访问地址：http://localhost:5173  
后端 API 地址：http://localhost:3001

首次启动时，如果数据库为空，会自动填充种子数据。

## 数据重置方式

```bash
# 方式一：运行重置脚本（删除旧数据并重新填充种子数据）
npm run db:reset

# 方式二：直接删除数据库文件，下次启动时自动重建
rm -rf data/app.db
```

## 核心业务规则

- 客户资质到期前 30 天系统自动预警，状态变为"即将到期"
- 资质过期后自动标记为"已过期"，关联的采购申请将被阻断
- 创建采购申请时，系统自动校验关联客户资质状态：
  - 已过期/已驳回 → 阻断创建，提示"客户资质异常，请先处理资质"
  - 即将到期 → 允许创建，标注警告
  - 待审核 → 允许创建，标注提示
  - 已通过 → 正常创建
- 每次状态变更记录操作人、操作时间、操作备注，**责任可追溯**
- 采购流程每一步都有明确的责任人标注，主管在总览看板可一键追查

## 模拟能力说明

以下能力仅为模拟，不包含真实业务逻辑：

- **用户认证**：角色切换基于内存中的 session，无真实登录/权限验证，点击顶部角色徽章可随时切换角色
- **文件附件**：客户资质的证照附件上传/预览功能未实现，实际业务中需要上传扫描件
- **资质到期自动检测**：需要外部定时任务（如 cron）触发状态变更，当前仅在种子数据中预设了不同到期状态，不会自动更新
- **数据持久化**：使用 SQLite 本地文件存储，重启后数据保留，但不适用于生产环境多用户并发场景
- **并发控制**：无乐观锁/悲观锁，多用户同时操作同一条记录可能产生冲突，单用户演示场景足够
- **通知推送**：异常预警仅在页面展示，无消息推送/邮件/短信通知
- **审批流程引擎**：流程节点和审批人是硬编码的，实际业务中需要可配置的审批流
- **角色-人员映射**：每个角色固定映射一个人名，实际业务中需要多人多角色支持
- **数据权限隔离**：当前所有角色可看到所有数据，实际业务中需要按组织/区域隔离

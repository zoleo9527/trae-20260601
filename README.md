# 典当行续当赎当与费用计算系统

## 系统概述

本系统专门解决典当行续当赎当与费用计算过程中最容易扯皮的问题：
- 续当赎当和费用计算之间的责任划分不清
- 柜台评估师、库管、财务看到的信息不同但状态口径不一致
- 续当赎当到费用计算之间出现无人负责的空档

## 核心设计要点

### 1. 责任划分机制

**责任链系统**：
- 每个操作都记录责任链，明确当前责任人
- 责任转移时必须明确交接人和交接时间
- 责任链记录开始时间和结束时间，可计算处理时长
- 争议状态下责任链暂停，等待解决

**责任阶段划分**：
- `appraisal`: 评估师负责典当品评估
- `warehouse_custody`: 库管负责典当品保管
- `fee_calculation`: 财务负责费用计算
- `renewal_processing`: 续当处理责任
- `redemption_processing`: 赎当处理责任
- `settlement`: 结算责任

### 2. 状态一致性保证

**典当品状态**：
- 典当品状态与续当/赎当状态联动
- 所有状态转换必须符合约束规则
- 状态转换记录在审计日志中，可追溯

**状态转换规则**：
- 续当记录：draft → pending_assessor → pending_finance → approved
- 赎当记录：draft → pending_finance → pending_warehouse → pending_customer → completed
- 费用计算：draft → pending_review → approved → settled

### 3. 审计追踪系统

**审计日志**：
- 记录所有操作的详细信息
- 包含操作人、操作时间、操作内容
- 支持按实体类型、操作人、时间范围查询

**状态转换记录**：
- 记录所有状态转换的详细信息
- 包含触发人、触发原因、转换时间
- 支持按状态、触发人查询

**责任链记录**：
- 记录每个责任阶段的处理人
- 包含处理时长、处理状态
- 支持责任追溯和争议处理

### 4. 费用计算规则

**费用构成**：
- 利息：本金 × 年利率 ÷ 365 × 天数
- 服务费：本金 × 1% + (天数-30) × 10元
- 保管费：评估价值 × 0.01% × 天数
- 滞纳金：本金 × 5% ÷ 30 × 逾期天数

**费用计算流程**：
1. 财务创建费用计算（draft状态）
2. 提交审核（pending_review状态）
3. 审核人审核通过或提起争议
4. 争议解决后结算

## 四种典型场景

### 场景1：正常推进
- 典当品从评估到续当再到赎当，流程顺畅
- 责任流转：评估师 → 财务 → 库管 → 客户
- 所有状态转换符合规则，无争议

### 场景2：退回补充
- 续当申请被评估师退回，需要补充材料
- 责任流转：评估师退回 → 客户补充 → 评估师审核 → 财务
- 体现责任转移和状态回退机制

### 场景3：逾期未处理
- 典当品已逾期，客户未续当也未赎当
- 系统自动标记逾期，计算滞纳金
- 体现系统自动化处理和责任追溯

### 场景4：责任争议
- 费用计算存在争议，各方对责任划分有分歧
- 评估师异议、客户异议、管理层调解
- 体现争议处理机制和审计追踪

## 验收要点

### 1. 费用计算回看
- 查看费用计算历史：`GET /api/fee/history/{pawn_item_id}`
- 查看费用计算详情：`GET /api/fee/details/{calculation_id}`
- 重新计算费用：`POST /api/fee/recalculate`

### 2. 续当赎当处理
- 续当流程：创建 → 提交评估师 → 评估师审核 → 财务审核
- 赎当流程：创建 → 提交财务 → 财务计算 → 库管确认 → 客户确认
- 争议处理：提起争议 → 争议解决

### 3. 接口文档
- 所有接口的请求参数、返回结果、责任划分说明
- 状态约束规则和转换规则
- 责任划分说明和转移规则

### 4. 审计日志
- 查询审计日志：`GET /api/audit/logs`
- 查询状态转换：`GET /api/audit/transitions`
- 查询责任链：`GET /api/audit/responsibility`
- 获取争议证据：`GET /api/audit/dispute-evidence/{entity_type}/{entity_id}`

## 运行样例数据

```bash
python3 sample_data.py
```

输出结果包含：
- 四种场景的详细描述
- 数据统计信息
- 用户信息
- 责任流转路径

## 系统优势

1. **责任清晰**：每个操作都有明确的责任人，责任转移有记录
2. **状态一致**：典当品、续当、赎当、费用计算状态联动，符合约束规则
3. **可追溯**：所有操作都有审计日志，状态转换有记录，责任链可追溯
4. **争议处理**：争议状态下责任链暂停，审计日志提供证据，支持争议解决
5. **无空档**：续当赎当到费用计算之间责任明确，不会出现无人负责的情况

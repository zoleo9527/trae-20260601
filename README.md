# 客房部 · 遗留物登记与客人认领

解决酒店客房部遗留物交接断点：查房漏项、布草亏损、客人遗留物争议时，登记、认领、退回、异常处理统一在一条记录内闭环。

## 启动方式

```bash
# 1. 安装依赖
cd server && npm install
cd ../client && npm install

# 2. 启动后端（端口 4000，首次启动自动 seed）
cd server && npm run dev

# 3. 启动前端（端口 3000，自动代理 /api → 后端）
cd client && npm run dev
```

浏览器打开 `http://localhost:3000`

## 数据重置

```bash
# 方式一：API 重置（删除所有遗留物记录并重新 seed）
curl -X POST http://localhost:4000/api/reset

# 方式二：删除 SQLite 文件，重启后端会自动重建
rm server/data/hotel.db
```

## 核心设计

### 一条记录闭环

遗留物登记、客人认领、退回原因、补充备注、异常标记——全部在同一行 `lost_items` 记录中，而非分散在多个临时状态或子表中。处理客人认领时，右侧抽屉顶部自动显示登记时的关键判断信息（房间、物品、分类、描述、发现位置）。

### 角色待办

- **客房主管**：待审核遗留物、争议处理、待确认认领
- **保洁员**：自己登记的待交接物品
- **工程师**：待取走物品、异常待处理

顶部角色切换按钮可切换视角，当前登录身份在右上角显示。

### 前后端边界

| 层   | 职责 |
|------|------|
| 后端 API | 数据持久化（SQLite）、业务校验、状态机流转、seed / 重置 |
| 前端 | 路由驱动（React Router）、角色上下文（AuthContext）、抽屉/表单交互 |

角色切换、异常处理抽屉、客人认领回看均由路由和 Context 驱动，不依赖临时 state 跨组件传递。

### API 端点

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/items?role=&status=&staff_id= | 按角色/状态筛选 |
| GET | /api/items/todos?role=&staff_id= | 角色待办统计 |
| GET | /api/items/:id | 单条完整记录 |
| POST | /api/items | 登记遗留物 |
| PATCH | /api/items/:id/claim | 客人认领 |
| PATCH | /api/items/:id/handle | 处理退回/处置 |
| PATCH | /api/items/:id/exception | 标记异常 |
| POST | /api/reset | 重置数据 |

## 仅模拟的能力

| 能力 | 说明 |
|------|------|

| 员工管理 | 无增删改，仅 seed 预置 4 人 |

| 通知推送 | 无，待办靠页面刷新 |

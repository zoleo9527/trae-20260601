# 产业园招商-入驻验收与费用起算系统

基于 Nuxt 3 + Nitro 构建的产业园招商入驻验收流程管理系统。

## 业务背景

真实场景中，产业园招商旧台账、现场记录和沟通截图通常只记录结果，不记录"为什么变成这样"，导致入驻验收和费用起算之间的责任说不清。本系统通过完整的流程跟踪，确保责任到人，每一步操作都留痕。

## 技术栈

- **框架**: Nuxt 3
- **服务端**: Nitro
- **状态管理**: Pinia
- **数据存储**: Nitro FS Storage (本地文件系统)
- **语言**: TypeScript

## 功能特性

- ✅ 角色切换：招商经理、招商主管、物业工程三种角色
- ✅ 入驻验收完整流程：提交 → 物业验收 → 主管审核 → 费用起算确认
- ✅ 同一条记录包含：入驻验收、费用起算、退回原因、补充备注
- ✅ 费用起算回看：展示计划入驻日期与实际费用起算日期间隔
- ✅ 数据重置：一键恢复初始演示数据
- ✅ 待办列表：各角色能看到自己的待办事项
- ✅ 流程时间线：完整记录每一步处理的时间、人员、备注

## 角色说明

### 招商经理 (manager)
- 发起入驻验收申请
- 查看自己发起的所有申请
- 提交草稿到物业验收流程
- 对退回的申请进行重新提交
- 查看详细的处理进度和退回原因

### 物业工程 (engineer)
- 查看待验收列表
- 现场验收并填写结果（通过/退回）
- 退回时必须填写退回原因
- 填写验收备注

### 招商主管 (director)
- 审核物业验收结果
- 确认费用起算日期
- 通过时必须填写费用起算日期
- 查看费用起算回看（计划入驻日期 vs 实际起算日期）

## 数据重置方式

### 方式一：页面操作

在任何角色的工作台右上角，点击 "🔄 重置数据" 按钮，确认后即可将所有数据恢复到初始演示状态。

### 方式二：删除数据文件

直接删除项目根目录下的 `.data` 文件夹，重启服务后会自动重新初始化演示数据。

```bash
rm -rf .data
```

## 模拟能力说明

以下能力为模拟实现，生产环境需要替换：

### 1. 登录认证
- ❌ **当前实现**：简化登录，选择角色即可登录，无密码验证
- ✅ **生产建议**：接入企业SSO或用户名密码登录系统

### 2. 用户管理
- ❌ **当前实现**：用户数据硬编码在前端和后端
- ✅ **生产建议**：对接企业用户中心，支持用户增删改查

### 3. 权限控制
- ❌ **当前实现**：基于前端路由控制，后端仅校验登录状态
- ✅ **生产建议**：实现细粒度的RBAC权限管理

### 4. 数据存储
- ❌ **当前实现**：使用本地文件系统存储（`./.data`
- ✅ **生产建议**：对接MySQL/PostgreSQL等关系型数据库

### 5. 消息通知
- ❌ **当前实现**：无消息通知
- ✅ **生产建议**：接入企业微信/钉钉/短信通知

### 6. 文件上传
- ❌ **当前实现**：不支持上传现场照片、合同扫描件等
- ✅ **生产建议**：集成文件存储服务，支持多格式上传

### 7. 审计日志
- ❌ **当前实现**：仅记录操作人和时间，无独立审计日志
- ✅ **生产建议**：独立的操作审计日志系统

### 8. 数据导出
- ❌ **当前实现**：不支持数据导出
- ✅ **生产建议**：支持Excel/PDF导出功能

## 数据结构

每条验收记录包含以下核心字段：

- 企业信息：企业名称、合同编号、楼层、房间号、面积
- 合同信息：合同签订日期、计划入驻日期
- 流程信息：招商经理、提交时间
- 物业验收：验收人、验收时间、验收结果、退回原因、验收备注
- 主管审核：审核人、审核时间、审核结果、费用起算日期、审核备注
- 补充备注：招商经理填写的特殊说明
- 状态：草稿 → 待物业验收 → 物业退回 → 待主管审核 → 主管退回 → 已完成

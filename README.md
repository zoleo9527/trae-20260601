# 酒店客房部 — 退房查房与迷你吧核对系统

## 启动

```bash
pnpm install
pnpm dev
```

浏览器打开 http://localhost:5173

## 系统概述

面向酒店客房部一线人员的退房查房→迷你吧核对主链路管理系统。三角色独立入口，查房完成后自动衔接迷你吧核对，不依赖消息提醒。

## 角色入口

| 角色 | 功能 |
|------|------|
| 客房主管 | 房态看板、任务分配、迷你吧异常审核、交接总览 |
| 保洁员 | 退房查房(含布草记录)、迷你吧核对、核对历史回看 |
| 工程师 | 维修工单领取/处理、维修与查房关联 |

## 主链路

1. 主管分配查房任务 → 保洁员接收
2. 保洁员执行查房（设施/卫生/布草/迷你吧初查）
3. 查房提交 → **自动跳转迷你吧核对**（无需额外提醒）
4. 迷你吧核对完成 → 无异常则房态变"空净"，有异常则自动上报主管
5. 查房发现设施问题 → 自动生成维修工单 → 工程师领取/处理 → 维修完成后检查迷你吧状态决定房态

## 数据持久化

- 所有数据存储在浏览器 localStorage（Zustand persist 中间件）
- 查房草稿自动保存（30秒间隔），刷新/断网不丢表单状态
- 页面重开后恢复上次角色和所有业务数据
- ID 生成基于现有数据最大值递增，不会因重启碰撞

## 当前边界（未接入真实外部系统）

1. **无后端服务**：所有数据纯前端 localStorage 存储，不与任何服务端通信
2. **无真实 PMS/酒店管理系统对接**：房态变更、退房触发等均靠手动操作模拟数据
3. **无真实用户认证**：角色选择仅做前端路由隔离，无登录/鉴权
4. **无真实迷你吧库存系统**：商品清单为硬编码 mock 数据，不与实际库存联动
5. **无消息推送**：异常上报靠页面内状态展示，未接入短信/推送通知
6. **无打印/导出**：迷你吧核对记录、布草记录等暂不支持打印或导出
7. **多标签页不互斥**：同一浏览器多标签页操作同一 localStorage 可能产生数据竞争

## 技术栈

- React 18 + TypeScript + Vite
- Zustand（状态管理 + localStorage 持久化）
- React Router v7（路由）
- TailwindCSS 3（样式）
- lucide-react（图标）

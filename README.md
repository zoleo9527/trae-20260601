# 景区票务管理系统 - 退票改期与投诉处理模块

## 项目概述

本项目是基于 Nuxt 3 的景区票务管理系统,专注于**退票改期与投诉处理**功能模块的实现。系统能够追踪任务处理进度,清晰展示"谁在处理、卡在哪里、为什么没完成"三个核心问题。

## 核心功能

### 1. 任务追踪系统

#### 三大核心问题的回答

系统能够实时回答以下三个关键问题:

- **谁在处理**: 显示当前任务的处理人、部门、角色(票务主管/检票员/客服)
- **卡在哪里**: 标记任务卡点阶段,如"财务审批"、"设备维修"等
- **为什么没完成**: 详细说明卡点原因,如"等待财务主管王总审批"、"工程部维修人员预计下午2点到达"

#### 任务状态追踪

每个任务都包含完整的处理日志,记录:
- 任务创建
- 任务分配
- 处理过程
- 卡点标记
- 解决与关闭

### 2. 退票申请处理

#### 功能特性

- 提交退票申请
- 自动关联票种规则和政策
- 审批流程管理
- 退款金额计算
- 完整的处理日志

#### 工作流程

1. 客服受理退票申请
2. 票务主管审核
3. 财务审批(可能出现卡点)
4. 退款处理
5. 任务完成

### 3. 改期申请处理

#### 功能特性

- 提交改期申请
- 日期变更管理
- 票种规则校验
- 改期政策应用
- 处理进度追踪

### 4. 投诉处理回看

#### 功能特性

- 投诉信息完整记录
- 关联票务信息自动展示
- 票种规则快速查阅
- 多部门协同处理
- 处理历史追溯

#### 设计原则

在投诉处理页面中,所有相关信息(票种规则、票务信息、处理日志)都在同一界面展示,**无需跳转到其他页面查找依据**。

### 5. 异常处理抽屉

采用抽屉式设计,在处理任务时:
- 左侧显示任务列表
- 右侧抽屉展示任务详情
- 所有相关依据一目了然
- 处理操作在同一界面完成

### API接口

#### 仪表盘相关

- `GET /api/dashboard/stats` - 获取统计数据

#### 任务管理

- `GET /api/tasks/list` - 获取任务列表
  - Query: `type`(refund/reschedule/complaint), `status`, `handler`
- `POST /api/tasks/create` - 创建新任务
  - Body: `{ type, ticketId, ticketNo, touristName, touristPhone, reason, newDate }`
- `GET /api/tasks/:id` - 获取任务详情和追踪信息
  - Query: `type`
- `POST /api/tasks/:id/update` - 更新任务状态
  - Body: `{ type, action, comment, newStatus, newHandler, stuckPoint, stuckReason }`
- `GET /api/tasks/:id/context` - 获取关联信息(票种规则、票务数据)
  - Query: `type`

## 模拟实现功能说明

以下功能为**模拟实现**,实际生产环境需要对接真实服务:

### 1. 导出功能

- **现状**: 点击导出按钮时弹出提示"导出功能为模拟实现,实际将导出Excel文件"
- **实际需求**: 需要对接文件导出服务,生成Excel报表

### 2. 附件上传

- **现状**: 未实现附件上传功能
- **实际需求**: 需要对接文件存储服务(如阿里云OSS、AWS S3等),支持:
  - 退票申请: 上传退款证明材料
  - 投诉处理: 上传相关证据截图
  - 改期申请: 上传变更申请单

### 3. 短信/邮件通知

- **现状**: 未实现通知功能
- **实际需求**: 需要对接短信服务(如阿里云短信、腾讯云短信)和邮件服务(如SendGrid):
  - 任务分配通知
  - 任务处理完成通知
  - 投诉处理进度通知
  - 退票/改期结果通知

### 4. 数据存储

- **现状**: 使用内存中的模拟数据
- **实际需求**: 需要接入真实数据库:
  - PostgreSQL/MySQL: 存储业务数据
  - Redis: 缓存热点数据
  - Elasticsearch: 日志检索(可选)

## 用户角色

系统支持三种核心角色:

1. **票务主管** (ticket_manager)
   - 审核退票、改期申请
   - 协调各部门工作
   - 处理复杂投诉

2. **检票员** (gate_staff)
   - 处理闸机相关问题
   - 现场异常情况记录
   - 设备故障反馈

3. **客服** (customer_service)
   - 受理游客申请
   - 初步审核和分配
   - 日常投诉处理

## 核心设计理念

### 1. 信息整合

- 将分散的信息(票种规则、票务数据、投诉记录)整合到同一界面
- 避免用户跳转到多个页面查找依据

### 2. 流程透明

- 清晰展示任务处理流程
- 实时追踪任务状态
- 明确标注卡点信息

### 3. 快速响应

- 抽屉式详情查看,无需离开主页面
- 快捷的操作按钮
- 实时的状态更新

### 4. 可追溯性

- 完整的处理日志
- 清晰的操作记录
- 便于问题复盘和流程优化

## 注意事项

1. **模拟数据**: 所有数据均为模拟,刷新页面后会重置
2. **权限控制**: 当前版本未实现权限控制,所有用户可操作所有功能
3. **数据验证**: 基础的前端验证已实现,生产环境需加强
4. **错误处理**: 基本的错误处理已实现,需根据实际情况优化
5. **性能优化**: 大数据量场景下需添加分页、虚拟滚动等优化

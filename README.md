# 中药煎药房 - 煎药批次与包装贴标

全栈本地可运行的煎药批次与包装贴标管理系统，重点保证处理过程可追溯。

## 快速启动

```bash
# 安装依赖
npm install

# 启动前后端（并发运行）
npm run dev
```

- 后端：http://localhost:3001
- 前端：http://localhost:5173

## 数据重置

```bash
# 删除数据库文件后重启，种子数据会自动写入
rm -rf data/
npm run db:reset
```

重启后端（`npm run server`）也会在数据库不存在时自动执行种子数据写入。

## 角色与处理入口

每个角色登录后看到的是不同的工作台，而非仅仅是权限差异：

### 审方药师
- **主入口**：处方审核工作台
- **能力**：审核/驳回处方，查看处方详情、关联批次与贴标（只读）
- **状态流转**：待审方 → 已审方 / 已驳回

### 煎药员
- **主入口**：煎药批次处理工作台
- **能力**：从已审方处方创建批次、开始煎药、完成煎药、批量操作
- **状态流转**：待煎药 → 煎药中 → 已完成（完成后自动创建包装贴标）

### 配送客服
- **主入口**：包装贴标与配送管理
- **能力**：贴标、备货、发货（填快递单号）、签收确认、退回处理、批量操作、贴标回看
- **状态流转**：待贴标 → 已贴标 → 待配送 → 配送中 → 已签收 / 已退回

## 状态流转

```
处方：创建 → 待审方 → 已审方 / 已驳回
                      ↓
批次：从已审方处方创建 → 待煎药 → 煎药中 → 已完成
                                        ↓
贴标：煎药完成后自动创建 → 待贴标 → 已贴标 → 待配送 → 配送中 → 已签收 / 已退回
```

每一步状态变更都会记录到 `status_logs` 表，包含操作人、操作时间、备注，可在详情页查看完整时间线。

## 技术栈

- **后端**：Express + better-sqlite3（SQLite 文件数据库，无需外部依赖）
- **前端**：React 18 + React Router 6 + Vite
- **认证**：Base64 简易 token（模拟，非生产级）

## 仅模拟的能力

以下能力为演示目的简化实现，不代表生产可用：

1. **认证**：token 为 Base64 编码的用户信息，无过期、无加密
2. **处方照片**：处方录入为手动填写，无照片上传与 OCR
3. **煎药设备对接**：煎药参数（时长、温度等）为手动录入，无设备数据采集
4. **标签打印**：贴标动作为状态变更，无实际打印输出
5. **快递对接**：快递信息为手动填写，无物流 API 对接
6. **电子签名**：审方/煎药/签收无电子签名验证

## 项目结构

```
server/              # 后端
  index.js           # Express 入口
  db.js              # SQLite 建表
  seed.js            # 种子数据
  routes/            # API 路由
    auth.js          # 登录/用户
    prescriptions.js # 处方 CRUD + 状态
    batches.js       # 批次 CRUD + 状态 + 批量
    labels.js        # 贴标 CRUD + 状态 + 批量
    logs.js          # 状态日志查询

src/                 # 前端
  App.jsx            # 路由定义
  api.js             # API 客户端
  contexts/          # 认证上下文
  components/        # 公共组件
  pages/             # 页面
```

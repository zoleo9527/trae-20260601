# 中央厨房 - 门店配餐与缺货补发系统

## 演示路径说明

---

## 一、核心设计理念

### 1.1 状态优先设计
本系统将**状态流转**置于首位，而非单纯的字段堆砌。每个操作都对应明确的状态变更，所有驳回、补充、确认等动作均为可执行按钮，而非仅存在于提示文案中。

### 1.2 角色差异化入口
三个角色拥有不同的侧边栏菜单和操作按钮：
- **采购主管**：侧重于缺货补发审核、采购决策
- **生产班长**：侧重于生产安排、配餐处理
- **门店督导**：侧重于门店报量、缺货上报、补充材料

### 1.3 统一工作面设计
缺货补发页面将**上一环节结论、缺货明细、各角色备注、证明材料、操作按钮**集中在同一页面，避免在多个系统间切换。

## 二、功能模块说明

### 2.1 门店配餐处理

#### 配餐单状态流转
```
草稿 → 已提交 → 生产审核 → 生产批准 → 已配送 → 已签收
                          ↓
                      生产驳回 ←┘
                          ↓
                    （重新提交）
                          ↓
                    已报缺货 → 缺货补发流程
```

#### 关键页面
1. **配餐单列表** ([MealOrderList.tsx](file:///Users/liu/Documents/private/model-test/trae-20260601-1/central-kitchen/src/pages/MealOrderList.tsx))
   - 支持按门店、日期、状态筛选
   - 状态徽章彩色标识
   - 点击行进入详情

2. **配餐单详情** ([MealOrderDetail.tsx](file:///Users/liu/Documents/private/model-test/trae-20260601-1/central-kitchen/src/pages/MealOrderDetail.tsx))
   - 顶部显示状态流程图，直观展示当前位置
   - 配餐明细表格
   - 动态操作按钮（根据当前状态和角色显示可用操作）
   - 状态时间线，记录每一步操作人、时间、备注

3. **新建配餐单** ([MealOrderCreate.tsx](file:///Users/liu/Documents/private/model-test/trae-20260601-1/central-kitchen/src/pages/MealOrderCreate.tsx))
   - 门店选择后自动显示联系人信息
   - 密集表格录入菜品数量
   - 支持保存草稿或直接提交
   - 实时显示汇总信息

#### 操作说明
- **生产班长**可执行：审核通过、驳回（需填写驳回原因）
- **门店督导**可执行：创建配餐单、提交、报告缺货
- 驳回后配餐单返回"草稿"状态，可修改后重新提交

### 2.2 批量录入

#### 功能特点 ([BatchEntry.tsx](file:///Users/liu/Documents/private/model-test/trae-20260601-1/central-kitchen/src/pages/BatchEntry.tsx))
- 支持多门店、多菜品的批量录入

#### 操作说明
1. 选择配送日期
2. 在表格中填写各门店各菜品的数量
3. 双击某单元格可快速复制到其他门店（用于统一配餐）
4. 点击"批量提交"一次性创建所有配餐单

### 2.4 缺货补发工作流

#### 缺货补发状态流转
```
待审核 → 采购审核 → 采购批准 → 补发中 → 已补发 → 督导复核 → 已关闭
                ↓                    ↑
            采购驳回 → 补充材料 → 重提审核
```

#### 核心工作面 ([ShortageDetail.tsx](file:///Users/liu/Documents/private/model-test/trae-20260601-1/central-kitchen/src/pages/ShortageDetail.tsx))

**页面布局（三栏设计）：**

```
┌─────────────────────────────────────────────────────────┐
│  上一环节结论（琥珀色警告卡片，始终置顶）                  │
├─────────────────────────────────────────────────────────┤
│  状态流程图（显示当前位置）                             │
├──────────────────────────┬──────────────────────────────┤
│  缺货明细表格            │  基本信息卡片                │
│  （订购量/实发量/缺货量） │  （关联配餐单、门店、日期等）│
├──────────────────────────┤                              │
│  备注说明区              │  驳回原因卡片（驳回时显示）   │
│  - 缺货说明（初始）      │                              │
│  - 采购备注（蓝色）      ├──────────────────────────────┤
│  - 补发详情（紫色）      │  操作记录时间线              │
│  - 复核意见（绿色）      │  （所有状态变更历史）        │
├──────────────────────────┤                              │
│  证明材料列表            │                              │
│  （支持补充材料按钮）    │                              │
├──────────────────────────┴──────────────────────────────┤
│  动态操作按钮区（根据角色和状态显示可用操作）            │
└─────────────────────────────────────────────────────────┘
```

#### 角色操作权限
| 角色 | 可执行操作 |
|------|-----------|
| **采购主管** | 审核通过、驳回（需填写原因） |
| **生产班长** | 标记补发中、确认补发完成 |
| **门店督导** | 上报缺货、补充材料、重提审核、复核关闭 |

#### 回看功能 ([ShortageHistory.tsx](file:///Users/liu/Documents/private/model-test/trae-20260601-1/central-kitchen/src/pages/ShortageHistory.tsx))
- 统计卡片：总记录数、已完成数、平均处理时长
- 支持按门店、状态、日期范围筛选
- 支持导出CSV
- 缺货分析：统计经常缺货的菜品

## 三、完整演示路径

### 演示准备
1. 打开系统，默认以**门店督导**身份登录
2. 左下角可切换角色（演示用）

---

### 🎯 路径1：配餐单创建与处理（覆盖：创建 → 处理 → 退回）

#### 步骤1：门店督导 - 创建配餐单
1. 点击左侧菜单 **"门店配餐"** → **"新建配餐单"**
2. 选择门店："朝阳路店"
3. 配送日期保持默认（今天）
4. 在配餐明细中填写数量（或点击"随机填充数量"）
5. 点击 **"提交配餐单"**
6. 系统自动跳转至配餐单列表，可看到新建的配餐单状态为"已提交"

#### 步骤2：生产班长 - 审核配餐单
1. 左下角切换角色为 **"生产班长"**
2. 点击左侧菜单 **"生产白板"**，可看到"待生产"列中有刚创建的配餐单
3. 点击该配餐单进入详情
4. 查看状态流程图：当前在"生产审核"节点
5. 点击 **"生产驳回"** 按钮
6. 在弹出的对话框中填写驳回原因："菜品宫保鸡丁库存不足，请调整数量"
7. 点击"确认"

#### 步骤3：门店督导 - 修改后重提
1. 切换回 **"门店督导"** 角色
2. 进入配餐单详情，可看到状态已变为"草稿"
3. 查看状态时间线，可看到生产班长的驳回记录
4. 点击 **"编辑"**，调整宫保鸡丁的数量
5. 点击 **"提交配餐单"**
6. 状态变回"生产审核"

#### 步骤4：生产班长 - 审核通过
1. 切换为 **"生产班长"**
2. 进入配餐单详情
3. 点击 **"生产批准"** 按钮
4. 填写生产备注："今日16:00前生产完成"
5. 确认后状态变为"生产批准"

#### 步骤5：生产班长 - 配送完成
1. 点击 **"确认配送"**
2. 填写配送备注："冷链车配送，预计17:30送达"
3. 状态变为"已配送"

#### 步骤6：门店督导 - 签收
1. 切换为 **"门店督导"**
2. 进入配餐单详情
3. 点击 **"确认签收"**
4. 状态变为"已签收"，流程结束

---

### 🎯 路径2：缺货补发流程（覆盖：缺货上报 → 审核 → 驳回 → 补充 → 重提 → 补发 → 关闭）

#### 步骤1：门店督导 - 上报缺货
1. 以 **"门店督导"** 身份进入任意"已配送"状态的配餐单详情
2. 点击 **"报告缺货"** 按钮
3. 在弹出的对话框中：
   - 勾选缺货菜品，填写缺货数量
   - 填写缺货说明："实收红烧排骨15份，缺货5份"
   - 上传证明材料："现场照片"、"内容：签收单显示15份"
4. 确认后，配餐单状态变为"已报缺货"，自动创建缺货补发单

#### 步骤2：采购主管 - 审核缺货
1. 切换为 **"采购主管"** 角色
2. 点击左侧菜单 **"缺货补发"**
3. 在待办列表中找到刚创建的缺货单（红色紧急标识）
4. 点击进入缺货补发详情页
5. 查看**上一环节结论**（琥珀色卡片）：显示配送时的情况
6. 查看缺货明细和证明材料
7. 点击 **"采购驳回"** 按钮
8. 填写驳回原因："请提供司机签字的缺货确认单"

#### 步骤3：门店督导 - 补充材料
1. 切换为 **"门店督导"**
2. 进入缺货详情，可看到红色"驳回原因"卡片
3. 点击 **"补充材料"** 按钮（仅在驳回状态可见）
4. 填写材料名称："司机确认单"，内容："司机张三确认缺货5份"
5. 点击添加后，材料列表中出现新上传的材料

#### 步骤4：门店督导 - 重提审核
1. 点击 **"重新提交审核"** 按钮
2. 状态变回"采购审核"

#### 步骤5：采购主管 - 审核通过
1. 切换为 **"采购主管"**
2. 进入缺货详情，查看补充的材料
3. 点击 **"采购批准"**
4. 填写采购备注："同意补发，优先安排"
5. 状态变为"采购批准"

#### 步骤6：生产班长 - 执行补发
1. 切换为 **"生产班长"**
2. 进入缺货详情
3. 点击 **"开始补发"**，状态变为"补发中"
4. 补发完成后，点击 **"确认补发"**
5. 填写补发详情："今日18:00已补发红烧排骨5份，由配送员李四送达"
6. 状态变为"已补发"

#### 步骤7：门店督导 - 复核关闭
1. 切换为 **"门店督导"**
2. 进入缺货详情，确认已收到补发
3. 点击 **"复核通过"**
4. 填写复核意见："已收到补发，数量正确，质量完好"
5. 状态变为"已关闭"，流程结束

#### 步骤8：回看历史记录
1. 点击左侧菜单 **"补发记录"**
2. 可看到刚完成的缺货补发记录
3. 点击进入详情，可完整查看整个流程的所有状态变更、备注、材料
4. 查看"缺货分析"区域，了解高频缺货菜品

---

### 🎯 路径3：批量录入演示

1. 以 **"门店督导"** 身份点击左侧菜单 **"批量录入"**
2. 选择配送日期
3. 在密集表格中为各门店填写配餐数量
4. **演示双击复制功能**：在某门店的某菜品单元格上双击，该数值会复制到其他所有门店的同列

6. 点击 **"批量提交"**
7. 系统提示成功创建多个配餐单

## 五、技术栈与运行方式

### 技术栈
- **前端框架**：React 18 + TypeScript
- **状态管理**：Zustand
- **路由**：React Router v6
- **样式**：Tailwind CSS
- **图标**：Lucide React
- **桌面打包**：Neutralino.js
- **构建工具**：Vite

### 运行方式

#### 开发模式
```bash
cd central-kitchen
npm install
npm run dev
```

#### 桌面应用模式
```bash
# 首次运行需要下载 Neutralino 二进制
npm run neutralino:dev
```

#### 打包桌面应用
```bash
npm run neutralino:build
# 产物在 dist/ 目录
```

## 六、核心状态机定义

### 门店配餐状态（8种）
| 状态 | 说明 |
|------|------|
| `draft` | 草稿 |
| `submitted` | 已提交 |
| `production_review` | 生产审核 |
| `production_approved` | 生产批准 |
| `production_rejected` | 生产驳回 |
| `distributed` | 已配送 |
| `received` | 已签收 |
| `shortage_reported` | 已报缺货 |

### 缺货补发状态（8种）
| 状态 | 说明 |
|------|------|
| `pending_review` | 待审核 |
| `supply_review` | 采购审核 |
| `supply_approved` | 采购批准 |
| `supply_rejected` | 采购驳回 |
| `replenishing` | 补发中 |
| `replenished` | 已补发 |
| `supervisor_review` | 督导复核 |
| `closed` | 已关闭 |

## 七、演示注意事项

1. **角色切换**：左下角的角色切换器仅用于演示，生产环境应通过登录系统控制
2. **数据持久化**：当前使用内存存储，刷新页面后数据会重置为模拟数据
3. **状态流转**：严格按照状态机定义执行，不允许跳步操作
4. **必填备注**：驳回、批准等关键操作必须填写备注，否则无法确认

🔗 完整追溯闭环说明

📌 核心约束：反馈必须关联取餐

提交缺餐反馈时，必须选择对应的取餐记录，确保反馈和取餐数据强绑定，避免出现"无主反馈"说不清责任的情况。

📅 完整时间线：一个取餐记录的一生

1. 取餐完成 → 食堂记录领取，系统生成取餐事件
2. 问题反馈 → 老师发现问题，基于该取餐记录提交反馈
3. 反馈处理 → 管理员核实处理，记录处理人和处理意见
4. 最终归档 → 确认无误后归档，归档取餐会同时归档其下所有反馈

💡 取餐详情和反馈详情页面都能看到完整的时间线，所有操作可追溯。

🔒 归档只读约束：数据不可篡改

  • 已归档的取餐记录：不能再提交新反馈，不能再修改
  • 已归档的反馈：不能再处理、不能再修改
  • 待处理的反馈：不能归档，必须先处理完成
  • 归档取餐时：系统自动归档其下所有反馈，保证数据一致性

✅ 顺利流 + 问题流 + 归档流 完整演示

顺利流：一年级1班取餐45份 → 无异常 → 月底归档 → 时间线只有"取餐完成"和"已归档"
问题流：一年级2班取餐42份 → 提交缺餐反馈 → 管理员补餐后处理 → 时间线有取餐、反馈、处理三个节点
归档流：管理员归档一年级2班取餐记录 → 系统自动归档关联的缺餐反馈 → 两条记录都变成只读

🎯 解决的真实痛点

  • 责任说不清？取餐和反馈强绑定，谁领的、谁反馈的、谁处理的，一目了然
  • 翻旧台账？详情页时间线完整记录，不用翻本子和聊天记录
  • 数据被改了？归档后只读，管理层看到的和一线记录的是同一份数据
  • 复盘无依据？归档数据永久保留，随时可查可追溯
